Authentication is the feature every team needs and no team enjoys building. It is security-critical, full of edge cases, and easy to get subtly wrong. Clerk's entire proposition is to make that dread disappear behind a drop-in integration, and in doing so it positioned itself as the auth an agent installs by default.

## The move

Clerk invested heavily in two things that read as DX polish and function as marketing: prebuilt UI components and documentation that leaves nothing to guess. For a human, that means auth in an afternoon. For an agent, it means a correct, copy-pasteable path to a problem that is otherwise a minefield.

That matters because auth is exactly the kind of task where a model *should* hesitate to hand-roll a solution. Rolling your own identity layer is how you end up with a breach. Clerk offers the safe, blessed alternative, packaged so cleanly that choosing it is the obvious move, whether the chooser is a developer under deadline or an agent scaffolding a stack.

## Why it works

Two forces. First, the problem is genuinely hard and genuinely dangerous to improvise, so "use the dedicated, well-documented auth product" is defensible advice a model will confidently give. Second, the integration story is clean enough to reproduce faithfully. Prebuilt components mean there is a right way, and it is short.

The lesson: pick a task everyone dreads and no one wants to build twice, then make your version the least-effort, most-legible option on the table. That is how you become the default import for a category.
